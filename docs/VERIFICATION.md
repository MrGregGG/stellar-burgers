# Результат проверки Stellar Burger

Дата: 15 октября 2026 года. Реализация: ветка `review`.

## Источники требований

- Приложенное задание «Stellar Burger. Роутинг и авторизация» в MHTML прочитано локально.
- Проверены исходный ZIP, API-методы, типы, UI-компоненты, страницы и конфигурация сборки.
- Приложенный `.fig` распакован; разобраны данные canvas и встроенное превью. В документе 8806 записей узлов. Найдены экраны конструктора, профиля, регистрации/входа, восстановления пароля, ленты, истории, деталей ингредиента и заказа.
- Сопоставлены основные размеры из макета: ширина содержимого 1240 px, формы 480 px, карточки ингредиентов/конструктор около 600 px, детали заказа 640 px, шапка 88 px; сохранены исходные CSS Modules, цвета, шрифты и библиотека компонентов.
- Отдельный официальный чек-лист по ссылке из исходного README недоступен. Неполученные критерии не объявляются проверенными.

В тексте задания одновременно есть указание оставить историю пустой и требование показывать реальные заказы. Реализовано итоговое функциональное требование: история показывает заказы пользователя. Для деталей используется номер заказа — это соответствует маршрутам из пошаговой инструкции и методу `getOrderByNumberApi`.

## Автоматические тесты

`src/services/store.test.ts` проверяет дубли ингредиентов, замену булки, границы перестановки, удаление, цену, счётчики, блокировку повторного заказа, сохранение состава при ошибке, успешный заказ, токены входа, отсутствие пароля в состоянии, профиль, восстановление сессии, локальный выход при ошибке сервера и запоздавшие ответы.

`src/utils/burger-api.test.ts` проверяет параллельное обновление токена, восстановление без access cookie, очистку при отказе refresh, запоздавший refresh после выхода и отсутствие повторов обычных серверных ошибок.

`src/components/protected-route/protected-route.test.tsx` проверяет гостевой и авторизованный доступ, ожидание проверки сессии, возврат на исходный маршрут и выбор background location.

`tests/browser.cjs` проверяет 10 групп сценариев на production-сборке: модалки и обновление URL; неизвестный ингредиент; повторяющиеся ингредиенты и клавиатурное управление; вход из конструктора и заказ; профиль; лента и детали; история и защищённые адреса; пустые списки и 404; восстановление пароля и регистрацию; повтор после ошибки API и консоль.

Все mocks находятся в тестах. Фиктивные данные не используются приложением при обычном запуске.

## Границы проверки

1. Реальный API из проверочной среды вернул HTTP 502. Вход, регистрация, PATCH, reset и создание заказа проверены на подменённых ответах, без реального тестового аккаунта. Утверждать проверку этих операций на живом сервере нельзя.
2. Макет изучен по локально разобранной структуре и встроенному превью; браузерные экраны просмотрены. Полного попиксельного сравнения с рендером Figma не выполнено. Необязательная мобильная версия из макета не разрабатывалась.
3. HTTP polling обеспечивает обновление раз в 15 секунд и сразу после собственного заказа. Это не push-подписка по WebSocket.
4. Webpack выдаёт предупреждения о размере бандла. Сборка завершается успешно; предупреждения не скрывались.
5. GitHub-репозиторий не указан. Push, Pull Request и merge не выполнялись. Для переноса подготовлены ZIP и Git bundle с ветками `main` и `review`.
