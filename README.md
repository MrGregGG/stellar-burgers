# Stellar Burgers

Учебное приложение космической бургерной: конструктор, лента заказов, регистрация, авторизация и личный кабинет.

## Запуск на Windows

Требуется Node.js 22 и npm. Проверки выполнены на Node.js 22.15.0.

1. Распакуйте архив и откройте папку `stellar-burgers` в VS Code.
2. Откройте терминал PowerShell в этой папке.
3. Выполните:

```powershell
npm install
npm start
```

Откройте **http://localhost:4000**. Для остановки сервера нажмите `Ctrl+C`.

API берётся из `BURGER_API_URL` в `.env.example`. Webpack использует этот файл по умолчанию. При необходимости локальной настройки:

```powershell
Copy-Item .env.example .env
```

Файл `.env` не добавляется в Git. Для работы с сервером требуется интернет. Собственный backend не нужен.

## Проверки

```powershell
npx tsc --noEmit
npm run lint
npm test
npm run build
```

Сборка находится в `dist`. Это SPA: при размещении на сервере настройте возврат `index.html` для неизвестных путей. Открытие `index.html` через `file://` не поддерживается.

Дополнительные браузерные проверки:

```powershell
npx playwright install chromium --only-shell
npm run test:browser
```

Браузерные тесты запускают временный локальный сервер готовой сборки и подменяют API только внутри тестового браузера. Они не создают реальные аккаунты и заказы. Обычное приложение использует настоящий API.

## Возможности

- Категории ингредиентов, переход по вкладкам и прокрутка.
- Замена булки, повторяющиеся начинки, счётчики, удаление и перемещение вверх/вниз.
- Цена: две половины булки плюс выбранные ингредиенты.
- Оформление заказа после входа; защита от повторной отправки; сохранение конструктора при ошибке.
- Регистрация, вход, выход, восстановление/сброс пароля и восстановление сессии.
- Редактирование профиля с отменой; пустой пароль не отправляется.
- Общая лента, статистика, личная история, статусы и состав заказов.
- Модальные маршруты и полноценные страницы при прямом открытии или обновлении адреса.
- Загрузка, серверные ошибки, повтор запроса, пустые данные и 404.

Ленты загружаются при открытии и после успешного заказа. Пока экран открыт и вкладка видима, данные дополнительно обновляются раз в 15 секунд. При уходе с экрана таймер удаляется. WebSocket не используется: проект работает с предоставленными HTTP-методами.

## Маршруты

| Адрес | Экран | Доступ |
|---|---|---|
| `/` | Конструктор | Всем |
| `/feed` | Общая лента | Всем |
| `/ingredients/:id` | Ингредиент | Всем |
| `/feed/:number` | Заказ | Всем |
| `/login`, `/register` | Вход и регистрация | Гостям |
| `/forgot-password` | Запрос кода сброса | Гостям |
| `/reset-password` | Сброс пароля | После успешного запроса кода |
| `/profile` | Профиль | После входа |
| `/profile/orders` | История | После входа |
| `/profile/orders/:number` | Заказ истории | После входа |
| Остальные адреса | 404 | Всем |

После входа восстанавливается запрошенный защищённый адрес. Сборка бургера сохраняется при переходе на форму входа внутри приложения; после полной перезагрузки конструктор начинается заново.

## Структура

- `src/components/ui` — исходные презентационные компоненты и стили.
- `src/components` — контейнеры, модальные окна, защита маршрутов.
- `src/pages` — страницы и формы.
- `src/services/store.ts` — RootReducer, store, типизированные hooks.
- `src/services/slices` — ингредиенты, конструктор, авторизация, заказ, общая лента, история и детали заказа.
- `src/services/selectors.ts` — категории, стоимость и счётчики.
- `src/utils` — API, cookies, токены, ошибки, правила модальных маршрутов.
- `src/**/*.test.ts(x)` — Jest: состояние, авторизация, API и маршрутизация.
- `tests/browser.cjs` — браузерные пользовательские сценарии.

Стек: React 18, TypeScript, Redux Toolkit, React Redux, React Router DOM 6, Webpack 5, CSS Modules и библиотека Stellar Burger.

Пароль хранится только в локальном состоянии формы и передаётся в запросе. Он не записывается в Redux state или localStorage. Redux DevTools отключён, чтобы аргументы auth-thunk не оставались в истории инструментов разработчика. Refresh token хранится в localStorage, access token — в cookie; конкурентные запросы разделяют одну операцию обновления токена.
